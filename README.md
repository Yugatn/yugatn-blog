# ЮГАТН · Авторский журнал / YUGATN · Independent Journal

Новый двуязычный блог (RU / EN) на GitHub Pages. Это **новая архитектура** без переноса старых постов, публичных презентаций или прежних меню.

## Статус
- `main` содержит только безопасную базу репозитория.
- Дизайн сайта разрабатывается через отдельную ветку и draft Pull Request.
- **Публикации на GitHub Pages ещё нет** — включение Pages и слияние ветки требуют отдельного согласования.

После утверждения и публикации сайта его адрес будет: `https://yugatn.github.io/yugatn-blog/`.

## Языки и страницы
- `/` — русский
- `/en/` — English
- `_posts/` — только утверждённые статьи (сейчас пусто)
- `_drafts/` — неопубликованные черновики, не попадающие в обычную сборку Jekyll

## Редакционный протокол
1. Новый материал готовится в **отдельной ветке**, а не в `main`.
2. Черновик помещается в `_drafts/`; на публичном сайте он не отображается.
3. Автор читает и явно утверждает финальную версию.
4. Только после утверждения создаётся файл `_posts/YYYY-MM-DD-slug.md` с `approved: true` и фиксированным `permalink`.
5. Предлагается Pull Request, который **не сливается автоматически**. Слияние — только после отдельного подтверждения автора.
6. Проверяем сборку и страницу; не изменяем первоисточники книг.

**Важно:** GitHub-репозиторий публичный: даже файлы в ветках и PR могут быть прочитаны на github.com. Для приватных черновиков нужен отдельный **закрытый** репозиторий или Notion; только итоговые утверждённые версии переносятся сюда.

## Пример метаданных статьи
```yaml
---
layout: post
title: "Название статьи"
description: "Краткая аннотация"
lang: ru
date: 2026-11-21
approved: true
permalink: /ru/articles/slug/
---
```

Содержание статьи пишется ниже YAML-блока. Для английского текста `lang: en` и `permalink: /en/articles/slug/`.

## Локальный просмотр
Нужен Ruby и Bundler. Установить зависимости `bundle install`, затем `bundle exec jekyll serve`. Открыть `http://127.0.0.1:4000/yugatn-blog/`.

## Развёртывание
После проверки PR и согласия автора: слить PR в `main`, открыть Settings → Pages, выбрать **Deploy from a branch**, ветку `main`, папку `/(root)`. Отдельно проверить, что сборка GitHub Pages прошла успешно.

## Защита от случайных публикаций
GitHub Actions `Blog publication guard` проверяет метаданные всех файлов `_posts/*.md`. Это дополнительная техническая защита, **а не замена авторского утверждения**.
